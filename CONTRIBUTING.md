# Contributing

Thanks for improving this project.

## Workflow

1. Create a branch with a clear name, such as `feat/audio-upload` or `fix/transcription-output`.
2. Keep changes focused and small enough to review.
3. Update docs when setup, audio, AI, or UI behavior changes.
4. Open a pull request using the template.
5. Include screenshots, audio notes, or short demos when useful.

## Quality Checklist

- Required docs remain present.
- Relevant checks pass.
- No secrets, private audio, transcripts, generated outputs, or `.env` files are committed.
- The PR explains the speech or user-facing impact.
